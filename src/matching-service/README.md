# Matching service

This directory contains the Python/FastAPI NLP matching service.

It exposes `GET /health`, `POST /internal/rank`, and `GET /feed/{candidate_id}`.
The ranking logic applies strict SQL hard rules (excluding non-published cards and
any card the candidate has already swiped) and ranks remaining cards using
semantic similarity (cosine similarity on embeddings generated by the Hugging Face
`all-MiniLM-L6-v2` Sentence Transformer model). If a candidate has no profile or
tags yet (cold start), cards fall back to most-recent-first (`published_at` DESC).

Ranking inputs use only candidate profiles, candidate/card tags, card job details,
and swipe/card IDs. Protected attributes and photos are never queried or accepted.
